In-flight operations

wp ops list

List in-flight operations

wp ops list <node> [flags]

Parameters to know

Parameter / type Use and default
--limit int Max results
--log int Filter by log ID
--longer-than int Only ops running longer than N ms
--seg int Filter by segment ID
--type string Filter by op type (e.g. file.flush)

Demo

wp ops list node-0 --longer-than 30000

Output and interpretation

OP_TYPE  OP_ID  TRACE_ID  LOG:SEG
# No rows means no matching tracked operation at this instant.

An empty table means no tracked in-flight operations at this instant, not no historical workload. Compare age and operation IDs over time.

Finding or error example 
logstore.add_entry  append-op-123  ...  42:7
# The same old operation across samples needs investigation.

wp ops show

Show detail of a single in-flight operation

wp ops show <node> [flags]

Parameters to know

Parameter / type Use and default
--op-id string Operation ID (required)

Demo

wp ops show node-0 --op-id append-op-123

Output and interpretation

Identity
  op_id: append-op-123
  op_type: logstore.add_entry
Context
  log_id: 42
  segment_id: 7

Copy a real OP_ID from ops list. A completed operation disappearing is expected; registry capacity is bounded. Replace append-op-123 with an ID returned by ops list.

Finding or error example 
Error: ResourceNotFound: ...
# It may have completed or been evicted since listing.

      --op-id string   Operation ID (required)

wp ops stats

Show op registry utilization and eviction statistics

wp ops stats <node> [flags]

Parameters to know

No additional operation-specific flags. Connection settings come from CLI setup.

Demo

wp ops stats node-0

Output and interpretation

Capacity
  capacity: 1024
  in_use: 0 (0.0%)
Eviction Totals
  old: 0

Counters can be cumulative. Compare snapshots and queue state; eviction can hide old operations, so no listed op is not always conclusive.

Finding or error example 
old: 12 (STALL SIGNAL)
# This counter is cumulative; sample again to see whether it is growing.
