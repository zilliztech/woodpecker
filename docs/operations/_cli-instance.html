Local data inventory

wp instance data

List the instances holding node-local data.

wp instance data [node] [flags]

Parameters to know

Parameter / type Use and default
--all Query every node in the cluster
--bucket string Filter to one instance's bucket (requires --root)
--root string Filter to one instance's root path (requires --bucket)

Demo

wp instance data --all --strict

Output and interpretation

NODE    BUCKET         ROOT_PATH  LOGS  SEGMENTS  LIVE  SIZE_BYTES  PROCS  DELETE_STATE
node-0  milvus-bucket  milvus/wp  1     2         1     1048576     1      active

Inventory local instances before deleting or draining. --bucket requires --root (this command uses --root, unlike segment --root-path). No CLI instance-delete command is currently registered; the scenario guide documents the admin API.

Finding or error example 
A node has scan_errors or is unreachable. A partial inventory does not establish that no data remains.
Complete command help 
List the instances holding node-local data.

Pair this with 'POST /admin/instance/delete' to reclaim an orphaned instance: query
first, decide, then delete only the nodes that reported the instance.

An unreachable node still holds its data, so a node shown as UNREACHABLE — or any
node reporting scan errors — means the picture is incomplete and nothing should be
deleted on the strength of it. Use --strict to turn that into a non-zero exit.

Usage:
  wp instance data [node] [flags]

Flags:
      --all             Query every node in the cluster
      --bucket string   Filter to one instance's bucket (requires --root)
  -h, --help            help for data
      --root string     Filter to one instance's root path (requires --bucket)
