wp logstore compact

Force compaction on a segment at an exact confirmed entry ID

wp logstore compact <node> [flags]

Parameters to know

Parameter / type Use and default
--expected-last-entry-id int Exact LastEntryId from coordinator metadata; an incorrect value can publish an invalid footer (-1 only for an empty segment, required)

Demo

wp logstore compact node-0 --log 2 --seg 0 --expected-last-entry-id 99

compact completed on node-0

wp logstore fence

Fence a segment on a single node.

wp logstore fence <node> [flags]

Parameters to know

Parameter / type Use and default
--log int Log ID (required)
--reason string Reason for fencing (required)
--seg int Segment ID (required)
-y, --yes Skip confirmation

Demo

wp logstore fence node-0 --log 2 --seg 0 --reason "Reviewed recovery"

Output and interpretation

About to fence log 2 segment 0 on node-0. Reason: Reviewed recovery
# Preview only; no -y means no fencing and exit code 7.

Changes write acceptance on one node. One-node fencing does not necessarily block an entire quorum; use fence-quorum for deliberate quorum intervention. Re-run with -y only after reviewing the node and quorum impact.

Finding or error example 
Missing writer / fence failure
Complete command help 
Fence a segment on a single node.

On a multi-node quorum this removes one acknowledgement and the write carries on through the rest; interrupting a write takes wq-aq+1 nodes, which is what `fence-quorum` does.

Usage:
  wp logstore fence <node> [flags]

Flags:
  -h, --help            help for fence
      --log int         Log ID (required)
      --reason string   Reason for fencing (required)
      --seg int         Segment ID (required)
  -y, --yes             Skip confirmation

wp logstore fence-quorum

Fence a segment across enough of its quorum to interrupt writes (high-risk, requires --reason)

wp logstore fence-quorum <logName> <segmentId> [flags]

Parameters to know

Parameter / type Use and default
--nodes strings Fence only these quorum members (default: every node in the quorum)
--reason string Reason for fencing (required)
-y, --yes Skip confirmation

Etcd connection flags: see CLI setup.

Demo

wp logstore fence-quorum my-channel 0 --reason "Verified writer recovery" --etcd 127.0.0.1:32379 --meta-prefix milvus-prod/woodpecker

Output and interpretation

Selected ...
# Preview only; without -y no RPC fencing is committed (exit 7).

The command previews quorum impact and requires acceptance (-y bypasses the prompt). Fencing can interrupt writes and trigger rolling/recovery; it does not repair data. Re-run the reviewed command with -y to commit.

Finding or error example 
Acceptance not given / too few selected reachable members
