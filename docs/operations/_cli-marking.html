Compacted-mark distribution

wp marking confirm

Confirm one compacted-mark distribution record.

wp marking confirm <logId> <segmentId> [flags]

Parameters to know

Parameter / type Use and default
--client-parameters-file string Private temporary etcd parameters file; not cli.yaml or a candidate profile
--force confirm (transition to OPERATOR_CONFIRMED) even if the record is not PENDING_MANUAL; IN_PROGRESS/COMPLETED are normally managed automatically
--standalone Use explicit etcd settings only; requires --etcd and --meta-prefix, skips context and Admin discovery

Etcd connection flags: see CLI setup.

Demo

wp marking confirm 2 0 --etcd 127.0.0.1:32379 --meta-prefix milvus-prod/woodpecker

Output and interpretation

Record set to OPERATOR_CONFIRMED

After verifying the permanently unavailable/unacked replica, settle notification retries. This preserves the record until truncation reaps it; it does not repair a segment or delete data immediately.

Finding or error example 
StateConflict for IN_PROGRESS / COMPLETED without --force
Complete command help 
Confirm one compacted-mark distribution record.

Meant for records parked as NOTIFY_PENDING_MANUAL: after verifying the unacked node
(typically permanently dead or removed from the cluster), confirm transitions the record
to NOTIFY_OPERATOR_CONFIRMED, which settles it (the auditor stops retrying and stops
counting it against the log). The etcd record itself is intentionally NOT deleted here;
it is reaped when the segment is truncated, like every other marking record.
Refuses records still IN_PROGRESS or COMPLETED unless --force is given (those are
managed automatically and normally need no operator action).

Usage:
  wp marking confirm <logId> <segmentId> [flags]

Flags:
      --client-parameters-file string   Private temporary etcd parameters file; not cli.yaml or a candidate profile
      --etcd string                     Required client etcd endpoints (comma-separated); independent of server context
      --etcd-cacert string              Local etcd TLS CA cert file; explicit per-run setting
      --etcd-cert string                Local etcd TLS client cert file; explicit per-run setting
      --etcd-key string                 Local etcd TLS client key file; explicit per-run setting
      --etcd-password string            Etcd auth password; explicit per-run setting
      --etcd-tls-min-version string     Etcd TLS min version (1.0/1.1/1.2/1.3); explicit per-run setting
      --etcd-username string            Etcd auth username; explicit per-run setting
      --force                           confirm (transition to OPERATOR_CONFIRMED) even if the record is not PENDING_MANUAL; IN_PROGRESS/COMPLETED are normally managed automatically
  -h, --help                            help for confirm
      --meta-prefix string              Required full client metadata prefix
      --standalone                      Use explicit etcd settings only; requires --etcd and --meta-prefix, skips context and Admin discovery

wp marking list

List compacted-mark distribution records (default: only NOTIFY_PENDING_MANUAL)

wp marking list [flags]

Parameters to know

Parameter / type Use and default
--all-states include IN_PROGRESS and COMPLETED records, not just PENDING_MANUAL
--client-parameters-file string Private temporary etcd parameters file; not cli.yaml or a candidate profile
--log int restrict to one log id (default: all logs)
--standalone Use explicit etcd settings only; requires --etcd and --meta-prefix, skips context and Admin discovery

Etcd connection flags: see CLI setup.

Demo

wp marking list --etcd 127.0.0.1:32379 --meta-prefix milvus-prod/woodpecker

Output and interpretation

COMPLETED / operator-confirmed records

Records describe compacted-mark distribution, not the data payload. Investigate unacked nodes and physical cleanup before manual settlement.

Finding or error example 
NOTIFY_PENDING_MANUAL with unacked nodes
