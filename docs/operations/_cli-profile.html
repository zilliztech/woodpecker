Profiles & trace

wp profile

Download a Go profile or execution trace from a node

wp profile <node> [flags]

Parameters to know

Parameter / type Use and default
--output-file string output file path (default: ./<node>-<type>-<timestamp>.pb.gz; trace uses .trace)
--seconds int duration for cpu/trace profiles (default 30)
--type string profile type: cpu|heap|goroutine|allocs|mutex|block|threadcreate|trace (default "cpu")

Demo

wp profile node-0 --type cpu --seconds 10 --output-file node0-cpu.pb.gz

Output and interpretation

Saved: node0-cpu.pb.gz
To analyze: go tool pprof -http=127.0.0.1:8081 node0-cpu.pb.gz

CPU uses /debug/pprof/profile. Trace uses go tool trace, not pprof, and saves .trace. allocs is cumulative allocation, heap is live memory; a sparse mutex profile does not prove absence of deadlocks. Goroutine pprof aggregates stacks; it is not a raw stack dump.

Finding or error example 
pprof returned status 404 / timeout
