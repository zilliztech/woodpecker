Troubleshooting

Choose one of three troubleshooting paths. Each starts with a short command plan, then shows detailed steps, result interpretation and recovery verification.

Choose the symptom

ScenarioStart whenMain path
Read StallsA reader/checkpoint is not advancing or the application waits for a WAL entry.Reader position → confirmed tail → replica probe → locate blocker → verify same-reader progress.
Write StallsAppends remain outstanding or durable confirmation stops.Submission → in-flight ops → writer queues → LAC → targeted recovery → append verification.
Data Corruption Diagnosis & RecoveryCRC/read errors, short replica coverage or replica coverage disagrees with the expected boundary.Metadata/data evidence → scan → probe/inspect → replica recovery, verified repair or accepted loss → application verification → checkpoint-backed retention.

Before running the steps

Complete CLI setup, including reachable admin origins for every quorum member. Each scenario includes a copyable connection block; replace its illustrative names and IDs with discovered values. Etcd parameters are used only by metadata-consuming commands.

Use the CLI built from the documented source checkout. Examples are illustrative excerpts; actual names, IDs and outcomes come from your deployment.

How to read a diagnostic result

ResultWhat it means
Idle / caught upNo new work may be available. Confirm workload and tail before declaring a stall.
Unknown / unreachable / cannot answerEvidence is incomplete. Restore transport, mappings or target location before treating it as missing data.
Short / checksum failure / all replicas failCorrelate with the finalized metadata boundary and identify the exact affected entry range.
Compacted / object_storageScan does not verify shared objects; probe can read them. Replies from three nodes may represent one shared copy.
Preview / acceptance not givenNo intervention was committed. meta patch/truncate previews normally exit 0; skip-range/fencing previews can exit 7 because acceptance was not given.
meta check: invalid / exit 9Metadata constraints failed; inspect issues. An independently verified metadata repair uses the guarded patch workflow, while physical damage needs its own recovery.
Command succeededVerify the application checkpoint/append result. An admin RPC succeeding is not the incident's closure.

Use the exit-code reference for scripts. For draining, configuration drift and disk inventory, use their CLI topic pages or the maintenance cookbook; these are separate from the three troubleshooting paths.
