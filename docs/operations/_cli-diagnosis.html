Native diagnosis

wp diagnose

Diagnose current WP service state or sample a live window using existing

wp diagnose [node] [flags]

Parameters to know

Parameter / type Use and default
--budget duration Whole-command wall-clock budget including discovery (max 10m) (default 1m0s)
--fail-on-findings Return exit 8 for suspected stalls after rendering the report
--interval duration Interval between live sampling rounds (default 1s)
--list List the implemented typed rule contracts without connecting
--max-nodes int Maximum discovered targets; select a node if exceeded (default 8)
--max-ops int Maximum ops per node per sample (1..1000) (default 100)
--max-response-bytes int Maximum bytes per discovery/source response (default 2097152)
--max-samples int Maximum sampling rounds per node (2..121) (default 31)
--max-series int Maximum retained completion-counter series per sample (default 500)
--mode string Observation mode: live|snapshot; no historical retrieval (default "live")
--scenario string Native scenario: all|stuck-write|stuck-read (default "all")
--window duration Live observation window starting now (max 5m) (default 30s)

Demo

wp --context milvus-prod diagnose node-0 --scenario stuck-write --window 30s -o json > write-report.json
# Current snapshot, without asserting sustained no-progress:
wp --context milvus-prod diagnose node-0 --mode snapshot -o json

Source-build capability. Reuses the WP service context and node Admin mappings; it does not select a tenant metadata namespace. Only stuck-write/read are implemented. --window samples from now; snapshot cannot prove a sustained stall. Exit 0 means completed evaluation, not healthy; --fail-on-findings opts into exit 8 for suspicions. Same-log completions cannot prove an individual op finished; resets, registry limits and missing evidence remain explicit. No external Prometheus, trace or Loki client is included. Missing evidence remains inconclusive rather than healthy.

Finding or error example 
PartialCollection (exit 6): required metrics/ops were unavailable; report retained.
Budget exhausted (exit 5) / cancellation (exit 7): partial evidence retained.
Complete command help 
Diagnose current WP service state or sample a live window using existing
metrics/Admin APIs. With no node argument, inspect all discovered nodes within
the target budget. Reuses cli.yaml, --context, --endpoint and node mappings.

Only stuck-write and stuck-read are implemented. Snapshot mode records current
evidence but cannot establish a sustained stall. --window starts sampling now;
historical Prometheus, trace and Loki queries belong to the separate tool.

Exit 0 means evaluation completed, including inconclusive/conflicting findings;
it is not a health assertion. --fail-on-findings returns 8 for suspected stalls.
Required collection failure returns 1 (all failed) or 6 (partial), cancellation 7,
and exhausted wall-clock budget 5. JSON/YAML evidence is retained on these errors.
