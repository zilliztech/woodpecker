Native diagnosis

wp diagnose

Diagnose current WP service state or sample a live window using existing

wp diagnose [node] [flags]

Parameters to know

Parameter / type Use and default
--budget duration Whole-command wall-clock budget including discovery (max 10m) (default 1m0s)
--fail-on-findings Return exit 8 for warning/critical findings after rendering the report
--interval duration Interval between live sampling rounds (default 1s)
--list List the implemented typed rule contracts without connecting
--log-name string Explicit WP-client metadata log; requires --segment, --etcd and --meta-prefix
--max-nodes int Maximum discovered targets; select a node if exceeded (default 8)
--max-ops int Maximum ops per node per sample (1..1000) (default 100)
--max-readers int Maximum reader records and lease checks per metadata sample (1..64) (default 16)
--max-response-bytes int Maximum bytes per discovery/source response (default 2097152)
--max-samples int Maximum sampling rounds per node (2..121) (default 31)
--max-series int Maximum retained completion-counter series per sample (default 500)
--max-writers int Maximum writer detail requests per node per sample (1..64; write/all) (default 16)
--mode string Observation mode: live|snapshot; no historical retrieval (default "live")
--read-mode string Expected reader use: unknown|tail|catch-up; not historical metrics retrieval (default "unknown")
--reader string Select one reader by exact name; otherwise inspect up to --max-readers
--scenario string Native scenario: all|write|read|stuck-write|stuck-read (default "all")
--segment int Explicit metadata segment ID for replica/reader checks
--window duration Live observation window starting now (max 5m) (default 30s)

Etcd connection flags: see CLI setup.

Demo

wp --context milvus-prod diagnose --scenario write --window 30s --max-writers 16 -o json > write-report.json
# Current disk admission; progress rules remain inconclusive:
wp --context milvus-prod diagnose node-0 --scenario write --mode snapshot -o json
# Optional replica check: select the Milvus WP-client metadata namespace explicitly.
wp --context milvus-prod diagnose --scenario write --log-name YOUR_LOG --segment 0 --etcd http://127.0.0.1:2379 --meta-prefix YOUR_WP_CLIENT_PREFIX -o json
# Native read scenario:
wp --context milvus-prod diagnose --scenario read --window 30s -o json > read-report.json
# Optional reader check with a suitable reporting window and explicit WP-client namespace:
wp --context milvus-prod diagnose --scenario read --read-mode catch-up --log-name YOUR_LOG --segment 0 --etcd http://127.0.0.1:2379 --meta-prefix YOUR_WP_CLIENT_PREFIX --window 65s --interval 5s --max-samples 14 --budget 90s -o json
# Existing focused append check:
wp --context milvus-prod diagnose node-0 --scenario stuck-write --window 30s -o json

Finding or error example 
PartialCollection (exit 6): required metrics/ops/writers were unavailable or writer details exceeded the bound; report retained.
Budget exhausted (exit 5) / cancellation (exit 7): partial evidence retained.
Complete command help 
Diagnose current WP service state or sample a live window using existing
metrics/Admin APIs. With no node argument, inspect all discovered nodes within
the target budget. Reuses cli.yaml, --context, --endpoint and node mappings.

Use --scenario write for append, flush, disk admission and explicit replica
checks, or --scenario read for activity, reader progress and quorum visibility.
Focused stuck-write/stuck-read retain their original v1 contracts. Snapshot mode
captures current evidence but cannot establish a sustained stall or buildup.
Reader progress needs the 30s client-profile reporting cadence and an explicit
read expectation. --window starts sampling now;
historical Prometheus, trace and Loki queries belong to the separate tool.

Exit 0 means evaluation completed, including inconclusive/conflicting findings;
it is not a health assertion. --fail-on-findings returns 8 for warning/critical findings.
Required collection failure returns 1 (all failed) or 6 (partial), cancellation 7,
and exhausted wall-clock budget 5. JSON/YAML evidence is retained on these errors.
