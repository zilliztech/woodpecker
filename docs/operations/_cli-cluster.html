wp cluster health

Red/yellow/green health check for the cluster

wp cluster health [flags]

Parameters to know

Parameter / type Use and default
--expected-replicas int expected replica count baseline (default 3) (default 3)

Demo

wp cluster health --expected-replicas 3

Output and interpretation

Cluster Health: GREEN

GREEN requires active > N, no unreachable/decommissioning nodes and no version skew. RED: active < N or any node unreachable. YELLOW: active == N, decommissioning or mixed versions. The default N=3 is a baseline, not inferred per-log quorum health.

Finding or error example 
Cluster Health: YELLOW
active: 3
zero redundancy (active == N)
Complete command help 
Red/yellow/green health check for the cluster

Usage:
  wp cluster health [flags]

Flags:
      --expected-replicas int   expected replica count baseline (default 3) (default 3)
  -h, --help                    help for health

wp node decommission

Trigger graceful node decommission (blocks until safe by default)

wp node decommission <node> [flags]

Parameters to know

Parameter / type Use and default
--async return immediately instead of waiting for safe_to_terminate
--heartbeat-interval duration heartbeat line interval when no progress change (default 15s)
--interval duration progress poll interval (default 3s)
--timeout duration overall timeout for the wait (default 30m0s)
-y, --yes skip interactive confirmation

Demo

wp node decommission node-0 --async

Output and interpretation

decommission started on node-0
# --async returns before drain completion; follow with drain-status.

Changes node lifecycle state. Check capacity first; --async returns after request rather than completion. Timeout does not authorize termination.

Finding or error example 
state=decommissioning remaining_processors=1 has_local_data=true safe=false
Complete command help 
Trigger graceful node decommission (blocks until safe by default)

Usage:
  wp node decommission <node> [flags]

Flags:
      --async                         return immediately instead of waiting for safe_to_terminate
      --heartbeat-interval duration   heartbeat line interval when no progress change (default 15s)
  -h, --help                          help for decommission
      --interval duration             progress poll interval (default 3s)
      --timeout duration              overall timeout for the wait (default 30m0s)
  -y, --yes                           skip interactive confirmation

wp node drain-status

Show (or watch) decommission progress for a node

wp node drain-status <node> [flags]

Parameters to know

Parameter / type Use and default
--interval duration watch poll interval (default 3s)
--timeout duration watch total timeout (default 30m0s)
-w, --watch continuously watch until safe_to_terminate

Demo

wp node drain-status node-0

Output and interpretation

safe_to_terminate: true

Terminate only after safe_to_terminate=true. active means decommission has not completed; processors and local data independently prevent a safe drain. -w polls.

Finding or error example 
state: active
remaining_processors: 1
has_local_data: true
safe_to_terminate: false
Complete command help

  wp node drain-status <node> [flags]

Flags:
  -h, --help                help for drain-status
      --interval duration   watch poll interval (default 3s)
      --timeout duration    watch total timeout (default 30m0s)
  -w, --watch               continuously watch until safe_to_terminate

wp node list

List all server nodes in the cluster

wp node list [flags]

Parameters to know

Parameter / type Use and default
--az string filter by availability zone
--region string filter by region
--rg string filter by resource group
--state string filter by state: active|decommissioning|decommissioned|unreachable|all (default "all")

Demo

wp node list --strict

Output and interpretation

NAME                  STATE   HEALTH
milvus-woodpecker-0    active  OK
milvus-woodpecker-1    active  OK

Use node IDs from this list in node-scoped commands; distinguish membership from HTTP reachability.

Finding or error example 
milvus-woodpecker-2    unreachable
# With --strict, incomplete fan-out returns a nonzero exit code.
Complete command help 
List all server nodes in the cluster

Usage:
  wp node list [flags]

Flags:
      --az string       filter by availability zone
  -h, --help            help for list
      --region string   filter by region
      --rg string       filter by resource group
      --state string    filter by state: active|decommissioning|decommissioned|unreachable|all (default "all")

wp node log-health

Show per-log read/write health observed by a node

wp node log-health <node> [flags]

Parameters to know

Parameter / type Use and default
--bucket string Filter to one instance's bucket (requires --root)
--root string Filter to one instance's root path (requires --bucket)

Demo

wp node log-health node-0

Output and interpretation

tracked: 1  healthy: 1  stalled: 0  failed: 0  idle: 0

Write/read health describe client/log activity tracked on this node. Idle is inactivity, not a checksum failure. Stalled and Failed require looking at operations and last failure; this registry is not a complete metadata inventory.

Finding or error example 
reason: idle_logs_present
tracked: 1  healthy: 0  stalled: 0  failed: 0  idle: 1
Complete command help 
Show per-log read/write health observed by a node

Usage:
  wp node log-health <node> [flags]

Flags:
      --bucket string   Filter to one instance's bucket (requires --root)
  -h, --help            help for log-health
      --root string     Filter to one instance's root path (requires --bucket)
